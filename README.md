# 开场 MATCHDAY · 像素足球

浏览器里的 11 对 11 单机足球。默认三分钟一场，也可选择一分钟热身或五分钟比赛。采用 TypeScript、Canvas 2D 和 Vite，无后端、无远程图片或音频依赖。

## 运行

```sh
npm install
npm run dev
```

打开页面，选择比赛时长，点击「开始比赛」。你控制红队，向右进攻。主罚时方向键瞄准，按住 J 或 K、松开出球；正式出球前对方不能抢，计时也不会开始。

## GitHub Pages 部署

仓库：<https://github.com/shihaojie0529/football-game>。首次部署需在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。

推送到 `main` 后，自动运行回归检查、构建并发布；也可在 Actions 中手动运行「Deploy game to GitHub Pages」。成功后访问 <https://shihaojie0529.github.io/football-game/>。

生产资源路径配置为 `/football-game/`，本地开发仍使用 `/`。本地预览运行 `npm run build` 和 `npm run preview`，打开 `http://localhost:4173/football-game/`。若改仓库名称，需同步修改 `vite.config.ts` 中的生产路径。

## 操作

右上角「按键设置」分为进攻、防守、通用三组：短传、射门、直塞、长传与切人、抢断、滑铲各自设置，修改进攻键不会改动防守键。攻防可复用同一键，同一状态内重复键自动互换；移动与冲刺等通用键同时作用于两种状态。旧版键位会自动迁移，修改自动保存在本浏览器。Esc 固定为暂停 / 返回。下表为默认键位，场内提示会跟随设置更新。

右上角「球员参数」按「我方 · 红队」「对方 · 蓝队」独立调整速度、粘球、传射、AI 跑位、协防和门将能力；球物理、规则和相机位于公共分组。可一键恢复全部默认，也可只恢复一队，恢复不清空当前比分。调整会在本次页面立即生效，比赛时长在重开时应用。默认门将已适度降低移动速度、反应速度和扑救范围，射正但来不及的球仍会尝试鱼跃。

| 按键 | 有球时 | 无球时 |
| --- | --- | --- |
| WASD | 移动；主罚时瞄准 | 移动 |
| Shift | 冲刺 | 冲刺 |
| J | 短传 | 手动切人 |
| K | 射门 | 站立抢断 |
| L | 直塞 | 滑铲 |
| I | 长传 | — |
| Esc | 暂停 / 继续 | 暂停 / 继续 |
| M | 开关音效 | 开关音效 |
| R | 打开重开选项；暂停或终场时重新开赛 | 同左 |
| F1 | 开关调参面板、模拟数据和 AI 目标点 | 同左 |

传球和射门都为按住蓄力、松开出球。很短的轻点也会保留到下一个模拟帧。使用物理键位识别，切换大小写或键盘布局不影响 WASD / IJKL。

绿色三角指示当前控制球员，黄色方框指示预定接球人。右下角雷达显示全场。传球后短暂保留传球者控制权，随后切换到接球人；不按方向键时自动迎球。

防守时会自动选择合适球员，J 可手动轮换。手动切人有保护时间。抢断较快，滑铲范围更大，但落空恢复更慢。

## 比赛流程

- 赛前：简短操作说明、时长和防守切人方式选择。
- 比赛：计分牌、剩余时间、随攻守变化的键位说明，以及取球 / 摆球 / 等待出球提示。
- 暂停：可直接调整防守切人方式；Esc 或暂停按钮；切换标签页或离开窗口也会自动暂停，返回后主动继续。
- 终场：胜负结果，以及双方射门、传球、成功抢断和控球率；可再来一场或返回赛前。
- 音效：踢球、哨声、进球和终场的程序音效，支持关闭。浏览器不支持音频时仍可比赛。

防守默认使用“辅助 · 仅空中球和无主球”：对方带球时不自动换人，按着方向跑位和松键后 0.35 秒保留当前后卫，同一次无主球争夺最多辅助切一次。J 只选择画面内未被小地图遮挡的队友：地滚球优先距球近，高球优先接近落点，距离相近时考虑球门侧站位。白色空心三角和 J 标出下一位；0.7 秒内连按只在附近最多三人间轮换；也可在赛前或暂停中选择“手动 · 按 J 切人”。本方接球依旧自动移交。门将无球时自动扑救，拿球后交给玩家。

正常带球、急停和转身不会自行丢球；第一脚停球会卸掉来球速度并收进身边。对手抢断、拦截和出界仍会改变球权。

我方门将拿球后不会自动开走：WASD 在禁区内移动并调整朝向，J 短传、L 直塞、I / K 开大脚，按住蓄力、松开出球。鱼跃落地和起身后可以操作；出球立即交回场上队友，门将恢复自动守门。

死球保护覆盖开场、进球后开球、任意球、界外球、角球和球门球。取球摆球由 AI 完成，玩家主罚必须实际出球才恢复比赛；对方会自动发球，我方球门球由玩家操作门将发出。

传球蓄力用于选择近处或远处的队友，选定后按实际距离和跑动提前量计算球速。接球时卸力；K 站立抢断成功会收球，L 滑铲则解围并需要起身。协防预判突破路线，近处队友倒地时自动换人接管，后方球员跟住突破方向补位。

对手会寻找可传的空位队友，避开越位位置和封堵线路，并在禁区附近转身瞄准射门。门将可预判、扑救和开大脚。双方统计来自真实模拟动作，进球后的开球保留累计数据，重新开赛才清零。控球率按活球时间计算，传球飞行期间归最后触球队伍，死球不计入。

## 结构

- src/sim：固定 60Hz 的纯数据模拟。attack.ts 负责持球 AI 决策，pass.ts / shot.ts 共用球物理。
- src/render：像素球场、球员动画、镜头、雷达和场内提示，只读模拟状态。
- src/input：键盘与短按缓冲。
- src/ui：赛前、暂停、赛后和比分 / 状态说明。
- src/audio：观察比赛事件并播放本地合成音效。
- src/main.ts：模拟、显示、输入和比赛流程的装配。
- src/tuning.ts：手感与 AI 参数；F1 可在运行时调整。
- DESIGN.md：历史设计决策及理由。

当前以桌面键盘为操作方式；窄窗口会保持球场比例，不提供触屏虚拟按键。暂不含联机、赛季、点球、牌、换人和体力系统。
